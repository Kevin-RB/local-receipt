# Receipt AI Analyser

A local-first web app that turns photos of paper receipts into structured, persisted data. The user uploads an image, a durable workflow extracts the text and parses it into a fixed contract, and the result is stored alongside the original image.

## Language

**Receipt**: A single paper receipt captured by the user, represented as one row in the database. It has a lifecycle from upload through extraction to completion. _Avoid_: Invoice, bill, order, transaction record.

**Receipt image**: The original JPEG or PNG file uploaded by the user. Stored as an object in MinIO. _Avoid_: Source image, raw image, photo.

**Object key**: The unique identifier MinIO uses to locate a receipt image inside a bucket. Generated by the server and stored on the receipt row. _Avoid_: File path, filename, S3 path.

**Upload**: The act of moving the receipt image from the browser into MinIO. The browser performs this directly using a presigned URL issued by the server. _Avoid_: Import, ingest.

**Presigned URL**: A short-lived, server-signed URL that grants the browser permission to write one specific object key to MinIO without exposing real credentials. _Avoid_: Upload token, signed link.

**Bucket notification**: An event MinIO sends to a configured webhook after an object is created. The server uses this as the authoritative signal that an upload finished. _Avoid_: MinIO webhook, SQS event, object event.

**Extraction**: The two-pass workflow that turns a receipt image into structured data: first transcribing the text, then parsing the transcript into the receipt contract. _Avoid_: OCR, parsing, analysis.

**Processing status**: The lifecycle state of a receipt row: `uploading`, `pending`, `processing`, `done`, or `error`. _Avoid_: Status, job state, run state.

**Integrity warning**: A flag on a completed receipt indicating the extracted line items do not sum to the stated total. The receipt is still stored, but the user is warned. _Avoid_: Validation error, mismatch flag.
